# Ghost-Tactics

A retro 2D tactical auto-battler for the classic **Apache + PHP + MySQL** stack.
It uses pure vanilla JS, HTML5 Canvas 2D and Web Audio. There are no frameworks, and the audio files total 0 KB.
All art comes from **one indexed-colour sprite atlas** built from the GHOST-TACTICS pixel asset pack.

| File | Purpose |
|------|---------|
| `index.php` | Game page: 4:3 canvas stage, responsive CSS, arcade modals, CSRF token, atlas loader |
| `game.js` | Engine: 3×6 grid, shop/bench/merge, drag & drop / tap-to-place, AI, 10 ghost skills, procedural levels, game-feel layer, leaderboard UI |
| `sound.js` | MSX/PSG synth: 3 square-wave channels + LFSR noise. 11 songs (title + 5 stages × prep/battle) plus boss variants derived at runtime, and 52 SFX |
| `sprites.png` | The atlas: one indexed-colour PNG (≈88 KB), 167 frames |
| `sprites.js` | Frame map generated by the builder: `name → [x, y, w, h, anchorX, anchorY]` |
| `save.php` | JSON API: progress save/load, rankings, high-score submission (`^[A-Z]{3}$`) |
| `config.php` | PDO MySQL connection + auto-migration |
| `db.sql` | Schema (`user_progress`, `rankings`) |
| `tools/` | Dev-only (blocked by `.htaccess`): the source sheet + `build_atlas.py` |

## Install

1. Copy the game into your web root (e.g. `htdocs/ghost-tactics/`).
   A server only needs `index.php`, `save.php`, `config.php`, `game.js`, `sound.js`, `sprites.js`, `sprites.png` and `.htaccess`.
2. Set your DB credentials in `config.php` (`DB_HOST` defaults to `localhost`), or with environment variables
   (`GT_DB_HOST`, `GT_DB_PORT`, `GT_DB_NAME`, `GT_DB_USER`, `GT_DB_PASS`, e.g. via Apache `SetEnv`).
3. Open `http://localhost/ghost-tactics/`.

With `GT_AUTO_MIGRATE` on (the default), missing tables are created on the first request; the DB user then needs the `CREATE` privilege until they exist.
You can also import the schema yourself: `mysql -u root -p < db.sql`. After that, a user with only `SELECT, INSERT, UPDATE` is enough.

Requirements: PHP 7.0+ with `pdo_mysql`, and MySQL or MariaDB 5.5+.
It is tested on PHP 7.0, 7.2, 7.4 and 8.3, with MariaDB 5.5 and 10.11.
The bundled `.htaccess` needs `AllowOverride All`. If Apache answers with a 500 error, delete `.htaccess`: the game still works, it just stops blocking direct access to files like `db.sql`.
If the database is unreachable, the game still runs: progress and high scores fall back to `localStorage`.

**Popup launcher:**
```html
<a href="#" onclick="window.open('ghost-tactics/index.php','ghosttactics','width=660,height=500');return false;">Play Ghost-Tactics</a>
```

## Asset pipeline ("cartridge" approach)

`tools/build_atlas.py` turns the 2000×1125 illustrated sheet into a tiny game-ready atlas:

1. **Parse.** The ghost animation grid (10 columns × IDLE/WALK/ATTACK/SKILL/HIT/DEATH/SPAWN) is located automatically from the sheet's divider lines. Frames are split at empty columns, and touching frames are split at mass valleys. Enemies, effects, icons, stage strips, tiles, props and text banners use explicit rects.
2. **Key.** The navy panel is removed by flood-filling from each frame's border through background-coloured pixels. Sprite outlines act as walls, and enclosed panel-coloured pockets become transparent.
3. **Reduce to native pixels.** The sheet is upscaled pixel art (enemies ~2.75×, animation frames ~1.4×, stage strips ~1.6×). Each sprite is reduced back to its native grid with a coverage-weighted box filter and binary (1-bit) alpha.
4. **Palette.** One 240-entry palette with index 0 transparent:
   - 103 colours shared by every character, effect and icon;
   - a 20-colour sub-palette per stage backdrop (weighted k-means that favours highlights such as the moon);
   - 6 colours per floor tile.

   Backdrops get a 3×3 majority filter. Isolated upscaler noise pixels in sprites are removed by 4-neighbour majority.
5. **Prune.** Only the frames the game uses ship. Each ghost keeps idle0/1, walk0/1, atk0/1, cast and spawn frames, plus its own projectile and skill effects where the sheet has them.
   - There are no HIT/DEATH frames or portraits. Hit reactions come from flash, knockback and squash, deaths from a dissolve, and shop cards show the idle frames.
   - Spawn bursts and projectiles are stored at half resolution and drawn at twice the scale.

The output is **≈88 KB** (one zopfli-optimised `sprites.png`) for 167 frames, including five full stage backdrops. The build fails if the PNG goes over a 96 KB budget.

The game draws every frame at **integer scale with nearest-neighbour** (2×; bosses 3×). It derives the rest at runtime for 0 extra bytes:
- the white hit-flash, red damage, charm-pink, curse-violet and dark variants, as tinted copies of the atlas made once at load;
- the 5×7 bitmap font and the outlined damage-number font (styled like the sheet's DAMAGE NUMBER art);
- the HP/MP bars, grid cells, brackets, particles, lightning and bandages.

The stage composites (strip at 3× plus tiled floor) are baked once per zone.

To rebuild after editing the sheet: `pip install pillow numpy scipy zopfli && python3 tools/build_atlas.py`.
Without `zopfli` the build still works, but the PNG comes out larger.

## How to play

- **Buy** ghosts from the 5-card shop by tap or click. They auto-deploy while there is room; otherwise they go to the 8-slot bench.
- **Deploy** by dragging, or tap a ghost and then tap a cell. Your side is the left 3 columns of the 3×6 grid. The unit cap grows with the level.
- **Merge:** 3 identical ghosts make a ★2 (×1.8 stats), and 3 ★2s make a ★3 (×3.24).
- **Synergy:** 2 or 4 distinct Western ghosts give +15% or +35% HP. 2 or 4 distinct Eastern ghosts give +15% or +35% ATK.
- **Altar:** a permanent +6% HP/ATK for the whole team, multiplicative.
- **Fight!** Units target the nearest foe, walk the grid, attack in range, fill MP and cast their skill (with a 200 ms telegraph).
- Winning pays gold (plus interest), and a boss appears every 10 levels. Losing costs a life; at 0 lives the game is over.
- Keys: `F`/`Space` fight · `R` reroll · `A` altar · `1-5` buy · `S` sell · `M` mute.

| Levels | Stage | Enemy skins (tank / melee / ranged) | Boss |
|---|---|---|---|
| 1–49 | Graveyard | Zombie / Skeleton / Ghost | Grave Ogre |
| 50–99 | Castle | Skeleton / Wolf / Bat | Castle Lord |
| 100–199 | Forest | Slime / Wolf / Spider | Forest Troll |
| 200–499 | Oriental | Zombie / Ogre / Ghost | Imugi |
| 500–999 | Hell | Ogre / Demon / Bat | Hell Wyrm |

Enemies are monsters **possessed by ghost spirits**. Each fights with its spirit's PRD skill. The INFO panel shows `SKELETON · SPIRIT: DRACULA`.

### Procedural levels (1–999)

Stage maps are never stored. Waves are generated deterministically from the level number:

```
HP  = BaseHP  * 1.045 ^ Level
ATK = BaseATK * 1.038 ^ Level      (BaseHP/ATK = spirit's base * 0.8; a boss has its own base: x3 HP, x1.5 ATK)
```

### Game feel

- **Hit-stop:** a global hit-stop (budgeted at ≤180 ms per second) plus a per-unit local freeze.
- **Shake:** trauma-based screen shake.
- **Hit reactions:** a white flash, then a red one on allies, plus eased knockback and squash & stretch.
- **Cast telegraph:** a ground ring and a blinking MP bar before each skill.
- **Crits:** basic attacks only, 10% chance for ×1.5, with damage variance compensated so that average damage is unchanged.
- **Damage numbers:** separate styles for normal, skill, crit, heal, DOT, block and execute.
- **Readability:** an HP damage trail, status icons and kill-streak callouts.
- **Finale:** a slow-motion final kill.
- **Banners:** STAGE CLEAR!! / LEVEL UP! / GAME OVER / TOP 10!.
- **Boss intro:** letterbox and nameplate, plus coins flying into the gold counter, a diamond wipe and zone cards.
- **Reduced motion:** respects `prefers-reduced-motion`.

## API (`save.php`)

| Method | Action | Body |
|--------|--------|------|
| GET | `?action=rankings` | none |
| GET | `?action=token` | none: returns a fresh CSRF token (the client calls it when its PHP session has expired) |
| POST | `rankings`, `new_game` | none |
| POST | `save_progress` | `player_id` (32 hex), `level`, `gold`, `lives`, `power`, `state` (JSON ≤ 8 KB) |
| POST | `load_progress`, `clear_progress` | `player_id` |
| POST | `submit_score` | `initial` (**must match `^[A-Z]{3}$`**), `level` |

POST requests need the `X-CSRF-Token` header; `index.php` issues the token in a meta tag.

There is also light anti-tamper protection:
- a run gains at most one level per second (`GT_ADV_MIN_S`; the fastest real win takes about 1.6 s), so 999 levels can't be forged in seconds;
- a run that lost saves while offline can catch up k levels once k seconds have passed since its last accepted advance;
- a score can't exceed the level that the session's run actually reached;
- each run can submit one score, and submissions are rate-limited.

### Saving

- **Battles are committed pessimistically.** Starting a battle saves the run as already lost, and the real result is saved the moment the battle ends. Reloading mid-fight or on the result screen can't undo a lost life.
- **Prep changes** (buy, sell, move, reroll, altar) are saved locally, debounced, so a reload keeps them.
- **CONTINUE** picks the newest snapshot, server or local, so progress made offline isn't rolled back.
- **Network calls time out after 5 s.** The game-over screen never waits on a stalled leaderboard request.
